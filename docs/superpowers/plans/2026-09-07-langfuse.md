# Langfuse Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deploy Langfuse (LLM observability) on the homelab K8s cluster using Helm, wired to existing CNPG Postgres, new in-cluster ClickHouse, existing Redis and Garage S3, accessible at `langfuse.naadroid.dev`.

**Architecture:** Three ArgoCD apps in sync-wave order: `clickhouse-operator` (wave 1, Helm), `clickhouse` (wave 2, raw CRs in `shared-data`), `langfuse` (wave 7, multi-source Helm). Langfuse web and worker pods connect to all four external datastores; nothing new is deployed inside the `langfuse` namespace except the app itself.

**Tech Stack:** Langfuse Helm chart 2.1.0 (app 4.24.0), ClickHouse operator `oci://ghcr.io/clickhouse/clickhouse-operator-helm` v0.0.5, CNPG Database CR, SealedSecrets, Istio ambient mesh, Istio Gateway HTTPRoute, Tailscale Ingress.

**Spec:** `docs/superpowers/specs/2026-09-07-langfuse-design.md`

## Global Constraints

- Homelab repo: `https://github.com/gunnervj/homelab.git`, branch `main`
- ArgoCD namespace: `argocd`; all Application CRs live in `clusters/home/root/apps/`
- Longhorn bulk storage class: `longhorn-bulk`
- Garage S3 endpoint (in-cluster): `http://garage.garage.svc.cluster.local:3900`, region `garage`, path-style required
- Redis (no auth): `redis.shared-data.svc.cluster.local:6379`
- Postgres read-write: `postgres-rw.shared-data.svc.cluster.local:5432`, user `admin`, DB `langfuse`
- ClickHouse service (after Task 2): `clickhouse.shared-data.svc.cluster.local`, HTTP port `8123`, native port `9000`
- Langfuse service port: `3000`
- External URL: `https://langfuse.naadroid.dev`
- Istio Gateway: name `homelab-gateway`, namespace `istio-ingress`
- cert-manager is already installed — do NOT reinstall it
- ClickHouseCluster apiVersion: `clickhouse.com/v1alpha1`
- KeeperCluster apiVersion: `clickhouse.com/v1alpha1`

# clusters/home/root/apps/clickhouse-operator.yaml

  name: clickhouse-operator
  namespace: argocd
  annotations:

### Task 6: Seal Langfuse secrets

**Files:**
- Create: `clusters/home/apps/langfuse/secret-sealed.yaml`

**Interfaces:**
- Consumes: `$CH_PASS` from Task 2, `$S3_KEY_ID` and `$S3_SECRET` from Task 4
- Produces: SealedSecret `langfuse-secrets` in `langfuse` namespace — Helm values in Task 7 reference its keys

- [ ] **Step 1: Generate the auth secrets**

```bash
NEXTAUTH_SECRET=$(openssl rand -hex 32)
SALT=$(openssl rand -hex 32)
ENCRYPTION_KEY=$(openssl rand -hex 32)
```

You also need:
- `$DB_PASS` — the CNPG admin password (same value used by keycloak's `db-credentials` secret — retrieve with `kubectl get secret db-credentials -n security -o jsonpath='{.data.password}' | base64 -d`)
- `$CH_PASS` — from Task 2 Step 1
- `$S3_KEY_ID` and `$S3_SECRET` — from Task 4 Step 3

- [ ] **Step 2: Seal the secret**

```bash
kubectl create secret generic langfuse-secrets \
  --namespace langfuse \
  --dry-run=client -o yaml \
  --from-literal=DB_PASSWORD=$DB_PASS \
  --from-literal=CLICKHOUSE_PASSWORD=$CH_PASS \
  --from-literal=S3_ACCESS_KEY_ID=$S3_KEY_ID \
  --from-literal=S3_SECRET_ACCESS_KEY=$S3_SECRET \
  --from-literal=NEXTAUTH_SECRET=$NEXTAUTH_SECRET \
  --from-literal=SALT=$SALT \
  --from-literal=ENCRYPTION_KEY=$ENCRYPTION_KEY \
| kubeseal --format yaml \
> clusters/home/apps/langfuse/secret-sealed.yaml
```

Do not commit raw values. Verify only the sealed file was written.
